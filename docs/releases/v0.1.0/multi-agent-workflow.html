并发冲突是怎么从根上消除的？ DAG 静态互斥
  1. 规划期硬校验：validate_plan 检查同一波次可并发任务之间的 write_scope，存在路径重叠直接拒绝规划，不进入执行期。
  2. 执行期物理隔离：每个任务从 accepted_overlay 克隆出独立 git worktree，彼此完全看不见对方未验收的中间态。
  3. 合入前门禁把关：只有同时通过 0-token 逃生舱、DiffGate（改了作用域外文件立即打回）和切片测试后，改动才合入 accepted_overlay。
为什么评审不会陷入“死循环或幻觉打回”？ Axis A 实证裁剪
  1. 用代码验证评审意见：Argus 提出的所有 Important 阻塞项都必须给出可复现命令 repro_command，由确定性的 Chronos 在沙盒中实际执行；跑不失败的“幻觉问题”直接被确定性裁剪丢弃。
  2. 修复后 0-token 复测：修复轮（hephaestus:repair-*）完成后，Chronos 直接重跑之前失败过的 repro_command 确认清零，再决定是否放行。
  3. 有界收敛：每个任务与 Post-DAG 均设 max_cycles 上限，耗尽即挂起转人工（AWAITING_HUMAN），绝不无限烧 Token。
