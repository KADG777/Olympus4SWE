Olympus4SWE v0.1 · 系统架构全景（main @ 1b4fc18）

确定性控制面 × 可插拔智能体执行面：从意图对齐到实机验收

核心不变量：LLM 只负责提出规格、方案、代码与评审发现；状态流转、SHA-256 哈希审批、互斥 write_scope、0-token 逃生舱门禁与预算账本全部由确定性代码掌管。

01 · System Topology

系统分层与数据流总览

为什么不会“越改越乱”？ 确定性保障
  • 不靠模型自觉：每个任务在独立 git worktree 施工，DiffGate 机械核对改动路径是否在 write_scope 内。
  • 0-token 先拦截：发现裸 # noqa、占位符或跳过断言直接打回，不浪费评审 Token。
为什么不会“自卖自夸”？ 冷启动独立性
  • 零共享对话历史：Momus 与 Argus 看不到施工者的思考过程，只看冻结契约、Diff 与真实执行输出。
  • 实机重启验库：verify_product.py 在洁净目录拉起应用，跑 Playwright 截图并在重启后二次验库。

02 · Pantheon SDLC Pipeline (full_sdlc_tdd)

全生命周期流水线：四阶段五神协同与三道人类门禁

Prometheus · Stage 1
需求对齐 (Align)
intake align critic gate_spec
只读摸底仓库，暴露 1–3 个阻塞歧义，支持补充反馈异步重合成，门禁冻结 EARS GoalSpec。
Athena · Stage 2a
设计与拆解 (Plan)
design gate_design plan gate_plan
锁定白盒接缝 DesignSpec，再用 swe-to-tickets 拆出骨架 + 垂直并行切片 DAG。
Hephaestus · Stage 2b
并行构建 (Build)
worktree 0-tok gate DiffGate
按波次并发执行切片；逃生舱门禁先拦投机代码，DiffGate 守卫作用域并运行单测。
Argus & Chronos · Stage 3
终态验收 (Verify)
post-DAG repair≤3 E2E
统一 Argus 复核 + 有界修复循环，最终在洁净目录启动产品并跑通 Playwright 重启验收。

04 · Hard Invariants

CI 强制架构红线

  • 控制面纯洁性：LLM 输出永不直接修改状态机、审批哈希、预算账本或 write_scope。
  • core/ 零耦合：禁止反向导入任何兄弟 olympus.* 包、LLM SDK 或 Web/CLI 框架。
  • SDK 隔离：全仓仅 providers/ 可导入 openai / anthropic。
  • 表现层单向依赖：核心与运行时层严禁导入 fastapi / typer / olympus.web。
  • 前后端契约同步：web/src/ 无纯 JS，改 API 必同步 openapi.json → schema.d.ts → static/。
